## 获取源码

仓库公开后，无需 GitHub 账号即可通过 Git 下载：

```sh
git clone https://github.com/YeGuiiiiii/rp-local.git
cd rp-local
```

需要与安装包一致的固定版本时：

```sh
git clone --branch v2.9.048 --depth 1 https://github.com/YeGuiiiiii/rp-local.git
```

Windows 如果提示文件名过长，下载时添加长路径选项：`git -c core.longpaths=true clone https://github.com/YeGuiiiiii/rp-local.git`。

其他平台可将仓库地址设为 `https://github.com/YeGuiiiiii/rp-local.git`，网页目录设为 `web`。仓库已包含编译后的网页资源，直接托管静态文件即可；本地预览、修改和 Android 打包见 [BUILDING.md](BUILDING.md)。网页预览不包含 Android 的私有文件、目录授权和后台恢复能力。

## 2.9.048 导入清单、导出回执与备份占用

本节包含 2.9.036～2.9.048 十三个小版本（versionCode 298～310）。2.9.048 已在真机确认可进入、能看到历史备份；**2.9.044～2.9.046 三个安装包存在装配缺陷、装机即闪退，不要安装**，详见下文。包名与签名不变，可直接覆盖升级。

- 2.9.048 导入清单与导出回执：导入大备份时列出的条目改为默认全选，并收进折叠栏，点开才能逐项取消；从备份历史打开、无法按位置跳读的包仍按 40MB 预算先选小批，避免为全选把大文件连读两遍。导出统一保存到 `Download/RP本地版`，保存成功后由系统提示真实路径，失败则明确报错，不再出现「失败却报成功」；角色卡、聊天、世界书、正则、预设分组等导出都接入回执。备份页显示备份文件夹占用（每日备份与手动导出分开计），新增「清理旧备份」，确认前写明删除数量与可释放体积，只删每日备份、不动手动导出的文件；每日备份默认保留份数由 5 改为 2 —— 一份备份接近整个数据库，默认留 5 份正是占用持续上涨的主因。「读取档位」改名「导入档位」并标注下限，旁边另显示本机实测单条上限，不再让人误以为仍写死 16/32/64MB。同时修掉切换外观时误报「上次导入没有正常结束」的问题：切换外观会重建界面，闲置的导入面板被当成中断记了一笔，现在只有真在导入时被卸载才留记录，历史里的假账也不再翻出。注意：「几天没备份」的提醒目前仍只看每日备份记录，尚未识别手动备份文件。
- 2.9.044～2.9.047 APK 装配事故与修复：2.9.044、045、046 三包装机即闪退、连界面都看不到，断网与全新安装都一样，且不产生 Java 崩溃日志。原因不在网页或存档，而在打包脚本：`.NET ZipArchive` 的 Update 模式在显式加载 `System.IO.Compression` 后会把整个 APK 重新编码，所有条目的 local flags 变成 `0x8`（声明使用 data descriptor）却实际没写 descriptor，同时丢失 UTF-8 标志位；Android 原生 zip 解析器在读取 assets 阶段直接 abort，native 层终止不经过 Java 异常处理器，所以没有 crash 日志。2.9.047 起改用 `scripts/finalize-apk.py` 确定性装配：`AndroidManifest.xml` 与 `classes.dex` 按 apktool 原始字节搬运（保留 `0x808` + descriptor），其余条目重建为 `flags=0x800`、无 descriptor，追加的 `classes2.dex` 为 `0x0`，与 2.9.043 同构。2.9.047 真机确认可进入；三份坏包的校验和已一并清理，不要据此重装。
- 2.9.042/043 导入收尾：第二趟入库改为按清点阶段记下的字节位置跳读，307MB 的包实测第二遍从 307MB 降到约 33MB，避免进度跑到 100% 后渲染进程被杀；顺带修复键名含引号的偏好项被截断、导致勾选项永远导不进来的问题。成功导入后不再误报「上次导入没有正常结束」，提示会写明中断在哪两个阶段之间；导入结尾「正在保存本机存档」与清理暂存库改为并行，等待缩短，这一步不能省略，否则同样的工作会挪到下次启动。
- 2.9.036～2.9.041 大备份导入：从「跳过但仍构造」改为按字节整段略过旧版自动备份快照（300MB 包里常有 160MB 以上这类快照），解析耗时约减半；核对阶段改为写入时顺手累加体积，不再回扫整个暂存库；导入中断会留下阶段、触发原因与内存占用记录；读取线程在解析收尾、暂存收尾、核对三处各报一次，配合每半秒跳动的心跳数字区分主线程卡死与读取线程卡住；超过 48MB 的备份导入前先清点并给出勾选清单，默认只勾 40MB 以内的一批。旧快照可整段剥离另存为「旧备份快照-日期.json」，不参与导入也不占应用空间。

安装包 `RP-local-2.9.048.apk`：versionCode 310，7,556,970 字节，SHA256 `b5db2d7c8aaf8fd7d700e42262146ac041e8edd2a2f3d9fcdb3a914b6ceeafe1`；校验和见 `dist/SHA256SUMS-2.9.048.txt`。2.9.036～2.9.047 不单独发布安装包，改动并入本版。设置页「几天没备份」识别手动备份文件、以及夜间模式切换免去重建界面，两项尚未实现。

## 2.9.035 大备份导入修复与单条上限动态放宽

本节包含 2.9.032～2.9.035 四个小版本（versionCode 294～297）。核心是修复 300MB 级备份导入报「当前字符串或单条记录超过 64 MB」的问题。签名不变，可直接覆盖安装。

- 2.9.035 单条上限动态放宽与旧版快照清理：导入时按本机实际可用堆内存计算单条上限——取「档位基准值」与「（堆上限 × 0.85 − 已用堆）÷ 2.5」中的较大者，最高放到 128MB；分块大小同步按堆容量调整（1MB / 512KB / 256KB 三档）。同一份备份在高配机上一次读完，在 4GB 机型上仍按档位基准保守读取。导入前若识别到旧版自动备份快照，会显示条目数与合计体积，并给出「导入后一并删除这些旧快照」的勾选项——默认不勾，需要明确选择才清理，避免删掉唯一的老存档副本。设置页「读取档位」的选项标注各档位对应的单条上限，并说明导入时会按可用内存自动放宽。
- 2.9.034 大备份导入失败修复：实测一份 307.1MB 的备份里有 163.9MB 是旧版自动备份快照——整份旧包的副本，当前版本既不读取也不参与还原，但它是一个单一的巨型字符串，导入时必然撞单条上限。现在导出时不再写入这类快照（备份体积直接减半），导入时解码器识别到就跳过，不解析也不占内存，所以旧包同样能导。导入失败提示改为显示具体键名、偏移量和当前单条上限，不再只有一句笼统的报错。设置页的「传输速度」改回「读取档位」——它管的是单条与单集合的上限，不是网速。
- 2.9.033 图标单色化与后台减负：功能面板里 `🧠 ⏸ ⏳ 📖 🖼` 这类会被系统强制渲染成彩色的 emoji，换成 `❖ ○ ⧗ ❧ ▣` 等不带 Emoji_Presentation 属性的单色符号，跟随界面文字色，深色主题下不再突兀。界面收敛五处：备份体积弹窗的 ZIP 堆明细收进折叠项、模型刷新改成标题旁的小按钮、图片固定选项压成单行、字体大小并入显示设置、运行环境卡片改成可折叠并在标题右侧直接显示内核版本与堆占用。流畅度方面把图片保存扫描、侧栏水印、名场面搜索、在线时长刷新等观察器与轮询做了合并和降频，滚动设置页时掉帧明显减少。
- 2.9.032 世界书与正则改动立即保存：修复世界书扫描深度、最大扫描深度未纳入自动保存 watcher、导致改完切页回档的遗漏；世界书与正则条目的新增、编辑、单条删除、批量删除及启用开关改为操作当下立即写入数据库，改完马上划掉后台也不会回档。经典皮肤补齐三处与默认皮肤不一致的保存触发点。

## 2.9.031 模型槽位扩展、备份导入提速与上游自动更新合入

本节包含 2.9.027～2.9.031 五个小版本（versionCode 293）。其中 2.9.029 的模型槽位与备份导入改动已真机验证；2.9.031 合入上游自动更新后建议更新后先确认设置页更新开关为关闭。签名不变，可直接覆盖安装。本地版本号 2.9.027～2.9.029 曾与上游撞号，已重排为 2.9.029～2.9.031。

- 2.9.031 模型槽位扩展到五个：快捷面板与模型选择器的槽位从三个加到五个，新增的两个槽位与其他三个一样按 API 站各自记忆、各有独立温度，未配置的槽位呈灰色不可点。快捷面板槽位区固定三行高，往下滑露出第四、第五个槽位，面板高度不变。本次同时合入上游的软件更新功能（设置页更新开关与检查更新，Wi-Fi 下下载并核对安装包后由系统确认安装）与版号竖排（常驻版号移到屏幕右下侧边竖向显示，避开输入框和工具按钮）；本地版更新开关默认为关闭，需要从上游服务器拉取更新时再手动开启。
- 2.9.030 导入与启动的时长提示：ZIP 大包导入的写库阶段、以及大数据库启动加载，原本只有一句「正在写入/仍在加载」，几分钟没反馈容易被当成卡死。现在写库阶段提示大包需数分钟、进度按条跳动属正常，启动页提示数据较多时需要一两分钟。导入与启动逻辑本身没有改动。
- 2.9.029 备份体检口径修正与 ZIP 峰值减半：数据体检的还原上限如实标注——.json 备份走流式导入不看堆上限，真正卡线的是流式档位的单集合与单条上限，体检会显示当前档位，最大数据桶超限时提醒换「高速」档或拆分备份。ZIP 导入改为读一条、删一条，解压缓存不再随条目累积，体积闸门按新峰值放宽约一倍。

### 图片保存修正

旧保存路径会把 WebView 内部的本地虚拟网址交给安卓 HTTP 下载器；安卓下载器无法读取这种只在 WebView 中存在的文件拦截。0.6 增加受目录限制的 `readImage` 接口，读取已保存图片的字节，再交给原生相册保存，不再用系统下载器访问内部网址。Blob 图片也走字节保存，远端生成结果链接保留原任务的鉴权参数。

远端返回 400 或伪装为图片的错误页面，会显示明确失败提示。保存时禁止请求 `/generate` 和新任务地址，不用重新生图来“修复下载”。本版没有真实手机故障时的网络日志，不能声称所有远端 400 都已解决；实测证据为本地文件、Blob、鉴权缺失模拟及 HTTP 400 模拟。
